# WhatNext Learning Knowledge Graph V2

**This is a curriculum knowledge graph, not a behavioral training dataset.** It is an expansion of the six existing human-curated study paths in `data/paths.json`, split into atomic, reusable learning concepts.

## Files
- `concepts.json` — canonical concept catalog, stable IDs, skill demonstration prompts and *proposed* prerequisite IDs.
- `topic_concepts.csv` — many-to-many relationship between original study topics and granular concepts.
- `career_concepts.csv` — deduplicated associations inferred from the above curriculum links; never claim these are measured employer requirements.
- `concept_prerequisites.csv` — directed prerequisite edges (source of truth: `concepts.json`).
- `graph.json` — compact browser-friendly complete graph with arrays of catalog records and their associations.
- `manifest.json` — lineage, counts, limitations, and validation.
 
## Rebuild / validate
```sh
node scripts/validate_learning_graph.mjs
node --test tests/test_learning_graph.mjs
```
The generated graph and CSV associations can be regenerated by `node scripts/build_learning_graph.mjs`. CI is deliberately not required.

## Boundaries
- These curriculum topics and dependencies are **editorial proposals**; not scientific evidence that any student needs the same path.
- `level` means indicative curriculum difficulty; it is **not** a student's assessed proficiency.
- `demonstration_task` is a suggested exercise, **not** a graded diagnostic item or labeled outcome.
- Inherited O*NET career SOC codes in V1 remain metadata, not proof of an individual learning requirement.
- No users, PII, grades, scraped records, success predictions or fake student observations are in this dataset.
- Prerequisite edges use `recommended_before`: not universally necessary, and allow direct proficiency assessments to override suggested ordering.
- Existing official resource links remain in V1 `learning_resources.csv`; V2 adds no unverified links.
- Career coverage remains six tracks from the existing app. Extend with source-grounded tracks and educational review before claiming comprehensive career coverage.

## App migration idea
Use `topic_concepts.csv` to connect existing roadmap cards to the canonical concept catalog. Track a student's **self-report** and **observed assessment evidence** separately. Derive eligible next concepts from prerequisite edges and the chosen career's concepts. Only later fit a neural ranker on consented, verified learning outcomes, benchmarked against the rules baseline.
